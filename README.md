# Feed

키워드를 등록하면 **네이버 · 구글 · 다음 · 네이트**에서 해당 뉴스를 주기적으로 수집하고, **중복 기사를 자동으로 합쳐** 한 화면에서 보여주는 로컬 웹 앱입니다.
외부 패키지 없이 Node.js만으로 동작하며, 선택적으로 **Gemini API(무료 등급)** 를 연결해 추천 키워드 판정과 카테고리 브리핑을 쓸 수 있습니다.

## 주요 기능

- **4개 포털 통합 수집** — 네이버·다음·네이트는 검색 결과 화면을, 구글은 뉴스 RSS를 읽습니다.
- **중복 기사 자동 제거** — URL이 같거나 제목이 거의 같으면 한 장의 카드로 합치고, 어느 포털에 실렸는지 배지로 표시합니다.
- **실시간 갱신** — 새 기사는 새로고침 없이 목록에 추가됩니다(SSE). 수집 주기는 30초~10분 중 선택합니다.
- **카테고리 / 키워드 관리** — 키워드를 카테고리(예: 보안, 투자)로 묶고, 왼쪽 메뉴에서 카테고리를 펼쳐 키워드별로 볼 수 있습니다. 등록·이동(드래그)·이름 변경은 `⚙ 키워드 관리` 화면에서 합니다.
- **★ 중요 필터** — 같은 카테고리 안에서 등록 키워드 2개 이상에 함께 잡힌 기사입니다. 카테고리별로 나눠서 볼 수 있습니다.
- **기사 보기 패널** — 기사를 클릭하면 새 페이지 대신 오른쪽 패널에서 본문을 읽습니다. 패널 폭은 드래그로 조절하며 저장됩니다.
- **추천 키워드 (시험 기능)** — 수집된 기사에서 자주·여러 언론사에서·키워드 2개 이상과 함께 나온 단어를 카테고리별로 추천합니다. 승인한 것만 등록됩니다.
- **✨ AI 기능 (선택, Gemini 무료 등급)** — 아래 [AI 기능](#ai-기능-선택) 참고.
- **오늘 이전 기사 제외** — 서버 PC 기준 오늘 0시 이전에 나온 기사는 새로 수집하지 않습니다. 이미 수집한 기사는 날짜가 바뀌어도 7일(최대 3000건) 동안 보관됩니다.
- **오늘만 보기** — 상단의 `오늘만` 토글(기본 켜짐)을 켜면 오늘 0시 이후 기사만 목록·메뉴 건수에 보이고, **카테고리 브리핑과 추천 키워드도 오늘 기사 기준으로 계산**합니다. 끄면 보관 중인 전체 기사를 기준으로 합니다. 브리핑은 두 범위를 따로 저장하며, 설정은 브라우저에 기억됩니다.

## 실행

Node.js 18 이상이 필요합니다(개발은 v22에서 진행).

```bash
node server.js
```

브라우저에서 http://localhost:3000 을 엽니다. Windows에서는 `start.bat`을 실행해도 됩니다(브라우저도 함께 열립니다).

포트를 바꾸려면 환경 변수 `PORT`를 지정합니다.

```bash
PORT=8080 node server.js
```

서버는 보안을 위해 `127.0.0.1`에서만 접속을 받습니다. 다른 기기에서 접속하려면 `server.js` 끝의 `listen` 주소를 변경하세요.

## 사용법

1. 왼쪽 아래 **⚙ 키워드 관리**를 엽니다.
2. 키워드를 입력하고(쉼표로 여러 개 가능) 카테고리를 지정해 **등록**합니다. 등록 즉시 수집이 시작됩니다.
3. 왼쪽 메뉴에서 `전체` / `★ 중요` / 카테고리 / 키워드를 눌러 필터링합니다.
4. 기사를 클릭하면 오른쪽에 본문이 열립니다. `Esc` 또는 ✕로 닫습니다. 패널 경계를 끌어 폭을 조절하고, 더블클릭하면 기본 폭으로 돌아갑니다.
5. 상단의 포털 체크박스로 특정 포털만 볼 수 있고, 🔔로 새 기사 알림을 켤 수 있습니다.

## AI 기능 (선택)

[Google AI Studio](https://aistudio.google.com)에서 API 키를 발급받아 연결하면 두 가지 기능을 쓸 수 있습니다. 키가 없으면 버튼이 비활성화될 뿐 나머지 기능은 그대로 동작합니다.

### 설정

왼쪽 메뉴 아래 **🔧 설정**에서 합니다. 서버를 다시 시작할 필요 없이 바로 적용됩니다.

- **Gemini API 키** — 붙여넣고 `저장`. `연결 테스트`로 키가 유효한지 확인할 수 있습니다(생성 호출이 아니라 일일 호출 한도를 쓰지 않습니다). `키 삭제`로 지울 수 있습니다.
- **모델 · 하루 호출 상한** — 앞에 적은 모델부터 사용하고, 한도·혼잡 오류가 나면 다음 모델로 넘어갑니다. 상한은 모델당 10~1000(기본 300)입니다.

입력한 값은 이 PC의 `.env` 파일에 저장됩니다(`.env`는 `.gitignore`에 포함되어 Git에 올라가지 않습니다). 화면에는 키를 다시 보여주지 않고 뒤 4자리만 표시합니다. 파일을 직접 편집해도 됩니다(`.env.example` 참고).

```
GEMINI_API_KEY=발급받은_키
# 선택
# GEMINI_MODELS=gemini-3.1-flash-lite,gemini-3.5-flash-lite
# LLM_DAILY_CAP=300
```

> 서버는 `127.0.0.1`에서만 접속되며, 설정·키 변경 같은 상태 변경 요청은 이 앱 화면에서 보낸 것만 허용합니다(다른 웹사이트가 보낸 요청은 거부).

### 기능

- **추천 키워드 AI 판정** — `⚙ 키워드 관리` → 추천 키워드 카드의 `✨ AI로 판정`. 후보를 `✓ 관련` / `일반어` / `✕ 무관`으로 분류하고 이유를 붙입니다. 결과는 3일간 저장되어 같은 후보는 다시 호출하지 않으며, 일반어·무관은 기본으로 숨깁니다.
- **카테고리 브리핑** — 카테고리·키워드·카테고리별 `★ 중요`를 선택하면 목록 위에 `✨ 브리핑` 카드가 나타납니다. `브리핑 생성`을 누르면 해당 카테고리의 최신 기사 제목(중요 기사 우선, 최대 60건)을 바탕으로 한 줄 총평, 주제 3~5개(근거 기사 링크 포함), 주목할 점을 보여줍니다. 같은 상태에서는 30분간 저장본을 재사용합니다.

### 호출 한도와 안전장치

- 무료 등급은 모델별 분당·일일 요청 한도가 있고 프로젝트 단위로 적용됩니다(일일 한도는 태평양 시간 자정에 초기화). 정확한 숫자는 AI Studio의 *비율 제한* 화면에서 확인하세요.
- 앱은 모델당 하루 호출 상한(기본 300)을 두고, 호출 사이를 4.6초 이상 벌리며, 한도·혼잡 오류가 나면 다음 모델로 넘어갑니다. 오늘 호출 수는 화면에 표시됩니다.
- AI가 만든 내용은 `AI 생성`으로 표시되며 틀릴 수 있습니다. 기사를 삭제하거나 수집 결과를 바꾸는 데는 쓰지 않고 참고용으로만 보여줍니다.

### 개인정보 / 데이터 전송

- AI 기능은 **버튼을 누를 때만** 외부로 전송하며(처음 누를 때 확인창이 뜹니다), 자동으로 보내지 않습니다.
- 전송 내용: 해당 카테고리의 **등록 키워드**, 추천 후보 단어, **기사 제목·언론사**. 카테고리 이름은 보내지 않습니다.
- Gemini API **무료 등급에 보낸 내용은 Google 제품 개선에 사용될 수 있습니다.** 민감한 키워드를 다룬다면 유료 등급 사용이나 조직 정책 확인이 필요합니다.

## 중복 제거 방식

- **URL 비교**: 추적용 파라미터(`utm_*` 등)를 뺀 주소가 같으면 같은 기사입니다. 구글 뉴스 링크는 리다이렉트 주소라 비교에서 제외됩니다.
- **제목 비교**: `[단독]`, `(종합)` 같은 말머리와 기호를 제거한 뒤, 제목이 같거나 한쪽이 다른 쪽에 포함되거나(말줄임 제목), 2-gram 유사도가 0.6 이상이면 같은 기사로 봅니다.
- 합쳐진 기사에는 포털별 링크가 모두 보존됩니다.

## 데이터 저장

`data/` 폴더에 저장되며 Git에는 포함되지 않습니다.

| 파일 | 내용 |
|---|---|
| `data/keywords.json` | 키워드, 카테고리, 수집 주기, 무시한 추천 후보 |
| `data/articles.json` | 수집한 기사(최대 3000건, 7일 보관) |
| `data/llm-usage.json` | 모델별 하루 AI 호출 수 |
| `data/llm-judgments.json` | 추천 키워드 AI 판정 결과 |
| `data/llm-briefings.json` | 카테고리별 브리핑 저장본 |

## API

모두 로컬 서버 내부용입니다.

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/state` | 키워드·카테고리·기사·수집 상태 |
| GET | `/api/stream` | 실시간 이벤트(SSE) |
| GET | `/api/article?id=` | 기사 본문 추출(구글 링크는 원문 주소로 변환) |
| POST / DELETE | `/api/keywords` | 키워드 등록(쉼표 구분, `group` 지정) / 삭제 |
| POST | `/api/keywords/group` | 키워드를 다른 카테고리로 이동 |
| POST / DELETE | `/api/groups` | 카테고리 생성·이름 변경 / 삭제 |
| POST | `/api/interval` | 수집 주기 변경(20~3600초) |
| POST | `/api/refresh` | 지금 수집 |
| GET | `/api/suggestions?scope=today\|all` | 추천 키워드 후보 (`today`: 오늘 기사, `all`: 보관 전체) |
| POST | `/api/suggestions/dismiss`, `/reset` | 후보 무시 / 무시 목록 초기화 |
| GET | `/api/llm/status` | AI 사용 가능 여부와 오늘 호출 수 |
| POST | `/api/suggestions/judge` | 추천 후보 AI 판정 (외부 전송) |
| GET / POST | `/api/briefing` | 저장된 브리핑 조회 / 카테고리 브리핑 생성 (외부 전송) |
| GET | `/api/settings` | AI 설정 상태(키는 마스킹된 뒤 4자리만) |
| POST | `/api/settings/llm` | API 키·모델·하루 상한 저장 (`.env` 에 기록) |
| POST | `/api/settings/llm/test` | API 키 연결 테스트 |
| DELETE | `/api/settings/llm-key` | 저장된 API 키 삭제 |

상태를 바꾸는 요청(POST/DELETE)에는 `X-Feed: 1` 헤더가 필요하고, `Origin`이 서버 주소와 다르면 403으로 거부됩니다.

## 파일 구성

```
server.js      수집(4개 포털) · 중복 제거 · 본문 추출 · 추천 키워드 · Gemini 호출 · HTTP/SSE 서버
index.html     화면 전체(HTML/CSS/JS 한 파일)
start.bat      Windows 실행 스크립트
.env.example   환경 변수 예시 (.env 로 복사해서 사용)
```

## 알아둘 점

- **화면 구조 의존**: 네이버·다음·네이트는 검색 결과 HTML을 파싱하므로, 포털이 화면 구조를 바꾸면 해당 포털만 결과가 0건이 되거나 오류가 날 수 있습니다. 이때 포털 이름 옆에 ⚠ 또는 ?가 표시되며, 다른 포털에는 영향이 없습니다.
- **다음 차단**: 요청이 많으면 다음이 캡차로 막을 수 있어 수집 주기를 너무 짧게 잡지 않는 것이 좋습니다.
- **본문 추출 한계**: 로그인·유료·스크립트 기반 사이트는 본문을 가져오지 못할 수 있습니다. 이 경우 패널의 `원문 열기`로 확인하세요.
- **추천 키워드는 시험 기능**: 형태소 분석기 없이 조사 제거·불용어 규칙으로 근사하므로 일반 단어가 섞일 수 있습니다. 승인 전에 사람이 확인하는 용도이며, AI 판정은 이를 보조합니다.
- **브리핑은 제목 기반**: 기사 본문이 아니라 제목만 읽고 요약하므로, 제목에 없는 맥락은 반영되지 않고 표현이 일부 구체화될 수 있습니다. 근거 기사 링크로 원문을 확인하세요.
- 각 포털의 이용 약관과 `robots.txt`를 확인하고, 개인적·내부 용도의 적정한 빈도로만 사용하세요.
