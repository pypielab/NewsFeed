# Feed

키워드를 등록하면 **네이버 · 구글 · 다음 · 네이트**에서 해당 뉴스를 주기적으로 수집하고, **중복 기사를 자동으로 합쳐** 한 화면에서 보여주는 로컬 웹 앱입니다.
외부 패키지 없이 Node.js만으로 동작합니다.

## 주요 기능

- **4개 포털 통합 수집** — 네이버·다음·네이트는 검색 결과 화면을, 구글은 뉴스 RSS를 읽습니다.
- **중복 기사 자동 제거** — URL이 같거나 제목이 거의 같으면 한 장의 카드로 합치고, 어느 포털에 실렸는지 배지로 표시합니다.
- **실시간 갱신** — 새 기사는 새로고침 없이 목록에 추가됩니다(SSE). 수집 주기는 30초~10분 중 선택합니다.
- **카테고리 / 키워드 관리** — 키워드를 카테고리(예: 보안, 투자)로 묶고, 왼쪽 메뉴에서 카테고리를 펼쳐 키워드별로 볼 수 있습니다. 등록·이동(드래그)·이름 변경은 `⚙ 키워드 관리` 화면에서 합니다.
- **★ 중요 필터** — 같은 카테고리 안에서 등록 키워드 2개 이상에 함께 잡힌 기사입니다. 카테고리별로 나눠서 볼 수 있습니다.
- **기사 보기 패널** — 기사를 클릭하면 새 페이지 대신 오른쪽 패널에서 본문을 읽습니다. 패널 폭은 드래그로 조절하며 저장됩니다.
- **추천 키워드 (시험 기능)** — 수집된 기사에서 자주·여러 언론사에서·키워드 2개 이상과 함께 나온 단어를 카테고리별로 추천합니다. 승인한 것만 등록됩니다.
- **오늘 이전 기사 제외** — 서버 PC 기준 오늘 0시 이전에 나온 기사는 수집하지 않습니다.

## 실행

Node.js 18 이상이 필요합니다(개발은 v22에서 진행).

```bash
node server.js
```

브라우저에서 http://localhost:3000 을 엽니다. Windows에서는 `start.bat`을 실행해도 됩니다(브라우저도 함께 열립니다).

포트를 바꾸려면 환경 변수 `PORT`를 지정합니다.

```bash
PORT=8080 node server.js
```

서버는 보안을 위해 `127.0.0.1`에서만 접속을 받습니다. 다른 기기에서 접속하려면 `server.js` 끝의 `listen` 주소를 변경하세요.

## 사용법

1. 왼쪽 아래 **⚙ 키워드 관리**를 엽니다.
2. 키워드를 입력하고(쉼표로 여러 개 가능) 카테고리를 지정해 **등록**합니다. 등록 즉시 수집이 시작됩니다.
3. 왼쪽 메뉴에서 `전체` / `★ 중요` / 카테고리 / 키워드를 눌러 필터링합니다.
4. 기사를 클릭하면 오른쪽에 본문이 열립니다. `Esc` 또는 ✕로 닫습니다. 패널 경계를 끌어 폭을 조절하고, 더블클릭하면 기본 폭으로 돌아갑니다.
5. 상단의 포털 체크박스로 특정 포털만 볼 수 있고, 🔔로 새 기사 알림을 켤 수 있습니다.

## 중복 제거 방식

- **URL 비교**: 추적용 파라미터(`utm_*` 등)를 뺀 주소가 같으면 같은 기사입니다. 구글 뉴스 링크는 리다이렉트 주소라 비교에서 제외됩니다.
- **제목 비교**: `[단독]`, `(종합)` 같은 말머리와 기호를 제거한 뒤, 제목이 같거나 한쪽이 다른 쪽에 포함되거나(말줄임 제목), 2-gram 유사도가 0.6 이상이면 같은 기사로 봅니다.
- 합쳐진 기사에는 포털별 링크가 모두 보존됩니다.

## 데이터 저장

`data/` 폴더에 저장되며 Git에는 포함되지 않습니다.

| 파일 | 내용 |
|---|---|
| `data/keywords.json` | 키워드, 카테고리, 수집 주기, 무시한 추천 후보 |
| `data/articles.json` | 수집한 기사(최대 3000건, 7일 보관) |

## API

모두 로컬 서버 내부용입니다.

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/state` | 키워드·카테고리·기사·수집 상태 |
| GET | `/api/stream` | 실시간 이벤트(SSE) |
| GET | `/api/article?id=` | 기사 본문 추출(구글 링크는 원문 주소로 변환) |
| POST / DELETE | `/api/keywords` | 키워드 등록(쉼표 구분, `group` 지정) / 삭제 |
| POST | `/api/keywords/group` | 키워드를 다른 카테고리로 이동 |
| POST / DELETE | `/api/groups` | 카테고리 생성·이름 변경 / 삭제 |
| POST | `/api/interval` | 수집 주기 변경(20~3600초) |
| POST | `/api/refresh` | 지금 수집 |
| GET | `/api/suggestions` | 추천 키워드 후보 |
| POST | `/api/suggestions/dismiss`, `/reset` | 후보 무시 / 무시 목록 초기화 |

## 파일 구성

```
server.js    수집(4개 포털) · 중복 제거 · 본문 추출 · 추천 키워드 · HTTP/SSE 서버
index.html   화면 전체(HTML/CSS/JS 한 파일)
start.bat    Windows 실행 스크립트
```

## 알아둘 점

- **화면 구조 의존**: 네이버·다음·네이트는 검색 결과 HTML을 파싱하므로, 포털이 화면 구조를 바꾸면 해당 포털만 결과가 0건이 되거나 오류가 날 수 있습니다. 이때 포털 이름 옆에 ⚠ 또는 ?가 표시되며, 다른 포털에는 영향이 없습니다.
- **다음 차단**: 요청이 많으면 다음이 캡차로 막을 수 있어 수집 주기를 너무 짧게 잡지 않는 것이 좋습니다.
- **본문 추출 한계**: 로그인·유료·스크립트 기반 사이트는 본문을 가져오지 못할 수 있습니다. 이 경우 패널의 `원문 열기`로 확인하세요.
- **추천 키워드는 시험 기능**: 형태소 분석기 없이 조사 제거·불용어 규칙으로 근사하므로 일반 단어가 섞일 수 있습니다. 승인 전에 사람이 확인하는 용도입니다.
- 각 포털의 이용 약관과 `robots.txt`를 확인하고, 개인적·내부 용도의 적정한 빈도로만 사용하세요.
